# start_points_claimer：START 云游戏积分任务自动领取助手

一句话：基于 Playwright 驱动真实浏览器，自动进入腾讯 START 云游戏（start.qq.com）积分任务面板并领取已完成任务的奖励，领取后顺带播报积分余额与最近过期时间，支持当日去重，专为挂 Windows 计划任务设计。

## 💡为什么需要？

- START 网页版的积分藏在「头像 → 我的资产 → 积分」三层菜单里，每天都得手动点一遍才能领"登录得积分"这类奖励
- 伪造接口请求需要逆向腾讯的加密登录态，风险高、极易失效；让脚本代替人手点击则完全无此烦恼
- 已完成的任务忘领不会累积，白白浪费积分（积分可兑换游戏时长）

**start_points_claimer 解决这些问题**：用一个带本地登录存档的"替身浏览器"，每天自动走一遍真实用户路径，看到"领取"按钮就点掉，行为和真人操作完全一致。

## ⭐亮点

- **零逆向、零伪造**：全程驱动真实 Chrome 点击，不碰任何私有接口，对平台而言就是一个正常用户
- **真实路径导航**：按「头像 → 我的资产 → 积分」逐层点击进入任务面板，不抄会触发"登录态失效"的近路
- **一次登录长期有效**：登录状态存本地 `profile/`，之后日常运行无需再扫码
- **当日去重**：同一天重复运行自动跳过，适合放心挂 Windows 计划任务
- **关键信息日志**：每次运行输出「[登录] 是否成功 → [检测] 有几项可领取 → [结果] 领了几项剩几项 → [积分] 当前总积分与最近过期时间」，运行情况一目了然
- **积分播报**：领取完顺手报出积分余额和最近一笔过期积分（多少分、哪天过期），不用再自己点进「积分明细」翻
- **零截图**：不生成任何图片文件，`logs/` 目录只放 probe 调试导出的文字
- **零配置**：所有参数写死在 `main.py` 顶部常量区，开箱即用，平台改版改常量即可
- **三合一 CLI**：`login`（扫码）/ `run`（领取，可 `--check` 只检测）/ `probe`（导出页面文字排查改版）一条命令各司其职

## 🚀快速开始

### 1. 克隆项目

```bash
# Gitee 镜像（国内访问快）
git clone https://gitee.com/yhl5244/start_points_claimer.git
cd start_points_claimer
```

### 2. 安装依赖

```bash
pip install -r requirements.txt
playwright install chromium
```

### 3. 首次登录

```bash
python main.py login
```

会自动弹出浏览器并点开登录框，用手机 QQ 或微信扫码即可；脚本检测到登录成功后自动保存状态并关闭窗口。

### 4. 日常运行

```bash
# 场景 1：无头后台运行，领取完自动退出
python main.py run

# 场景 2：弹出浏览器窗口，围观它点
python main.py run --visible

# 场景 3：每天定时自动运行（Windows 计划任务，时间改为你想要的）
schtasks /create /tn "START云游戏领积分" /tr "\"C:\Python312\pythonw.exe\" \"C:\start_points_claimer\main.py\" run" /sc daily /st 09:30 /f
```

> 场景 3 用 `pythonw.exe` 运行全程无弹窗；计划任务里 Python 必须写完整路径，Linux 用户改用 crontab 即可。

## ⌨️CLI 模式

```text
python main.py <login | run | probe> [选项]
```

### 通用选项

| 参数 | 说明 |
|------|------|
| `--version` | 查看版本号 |

### login

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--wait` | 等待扫码的最长秒数 | `300` |

### run

| 参数 | 说明 |
|------|------|
| `--visible` | 弹出浏览器窗口运行（默认无头） |
| `--keep-open` | 领取完不关浏览器，方便人工检查 |
| `--force` | 忽略当天已运行记录，强制再跑一次 |
| `--check` | 只检测有几项可领取，不点击（忽略当日去重，不写 state.json） |

退出码：`0` 成功（含"今天已跑过"跳过）/ `1` 登录超时或运行异常 / `2` 未登录（先跑 `login`）

### probe

无额外参数。走到任务面板后把每个 frame 的可见文字导出到 `logs/dom_dump.txt`，用于页面改版时对照更新 `main.py` 里的 `CLAIM_KEYWORDS`。

## ⚙️参数调整

本项目**零配置、开箱即用**。所有匹配规则集中写在 `main.py` 顶部「内置参数」区，想调整行为直接改常量：

| 常量 | 说明 | 默认值 |
|------|------|--------|
| `HEADLESS` | 无头后台运行 | `True` |
| `CLAIM_KEYWORDS` | 可领取按钮的文案（全字匹配） | `一键领取 / 领取 / 领取奖励` |
| `SKIP_WORDS` | 含这些字样的一律不点 | `已领取 / 去完成 / 前往 / ...` |
| `MAX_ROUNDS` | 领取后最多再扫几轮 | `4` |
| `ENTRY_ASSETS` / `ENTRY_POINTS` | 任务面板入口路径文案 | `我的资产` → `积分` |
| `LOGIN_WAIT_SECONDS` | login 等待扫码秒数 | `300` |

## ❓️FAQ

**每次运行都要扫码吗？**

不用。`login` 扫一次码后，登录状态保存在 `profile/` 目录；日常只跑 `run` 即可。腾讯扫码登录一般能维持很久，若哪天提示"未检测到登录状态"，重新 `login` 一次即可。

**会不会被腾讯封号？**

脚本不伪造任何请求，只是在真实浏览器里点击真实页面上的按钮，对平台而言和一个正常用户没区别。但请遵守平台规则，仅用于自动领取你本人账号已完成任务的奖励。

**运行后显示"领取 0 次"是坏了吗？**

大概率是当天的任务已经领完了，属正常现象。可以先跑 `python main.py run --check` 只检测不领取，或用 `python main.py probe` 导出页面文字对照确认；若发现按钮文案变了（如"立即领取"），把新文案加进 `main.py` 的 `CLAIM_KEYWORDS` 即可。

**积分余额和过期时间怎么来的？准吗？**

领取完脚本会顺手点开商城页头的「积分明细」，读里面「可用平台积分」和「N 积分将于 X 年 X 月 X 日过期」两行文字，所以报的就是页面上显示的真实数字，与人工点进去看到的一致；页面上没有过期提示时，日志只报总积分并注明"未读到积分过期信息"。

**支持 macOS / Linux 吗？**

代码本身跨平台（纯 Playwright），登录与点击流程在 macOS/Linux 上同样可用；只有"计划任务"章节的 `schtasks` 命令是 Windows 专属，Linux 用户改用 crontab 即可。

**为什么不用 requests 直接调接口？**

START 的登录态带加密签名，伪造请求需要逆向且极易被风控；本项目用真实浏览器模拟，稳定性与合规性都更好，代价仅是需要装一个 Chromium。
