# start_points_claimer：START 云游戏积分任务自动领取助手

一句话：基于 Playwright 驱动真实浏览器，自动进入腾讯 START 云游戏（start.qq.com）积分任务面板并领取已完成任务的奖励，领取后顺带播报积分余额与最近过期时间，支持登录态自动保活与当日去重，专为挂 Windows 计划任务设计。

## 💡为什么需要？

云游戏最大的好处是**不吃本机配置**——不用下载几十个 G 的客户端，也不用管显卡够不够，打开浏览器登录就能玩，随手清个体力、刷个日常特别省事。

但正因为门槛这么低，云游戏平台普遍用每日任务把人拴住：每日登录给积分、玩满几分钟给积分、连续登录还有额外奖励……积分能换游戏时长，可领起来一点都不轻松：

- START 网页版的积分藏在「头像 → 我的资产 → 积分」三层菜单里，每天都得手动点一遍才能领"登录得积分"这类奖励
- 伪造接口请求需要逆向腾讯的加密登录态，风险高、极易失效；让脚本代替人手点击则完全无此烦恼
- 已完成的任务忘领不会累积，白白浪费积分（积分可兑换游戏时长）

**start_points_claimer 解决这些问题**：用一个带本地登录存档的"替身浏览器"，每天自动走一遍真实用户路径，看到"领取"按钮就点掉，行为和真人操作完全一致。

## ⭐亮点

- **零逆向、零伪造**：全程驱动真实 Chrome 点击，不碰任何私有接口，对平台而言就是一个正常用户
- **真实路径导航**：按「头像 → 我的资产 → 积分」逐层点击进入任务面板，不抄会触发"登录态失效"的近路
- **少扫码**：登录状态存本地存档，日常只跑 `run` 不碰扫码；电脑 QQ 在线时连首次登录都免扫码
- **掉线自动自救**：凭据失效时依次尝试现有存档、凭据备份、QQ 快捷登录自动重登，全程无需人工、不弹窗
- **当日去重**：同一天重复运行自动跳过，适合放心挂 Windows 计划任务
- **积分播报**：领取完顺手报出积分余额和最近一笔过期积分（多少分、哪天过期），不必再翻「积分明细」
- **零截图、零配置**：不生成任何图片文件，所有参数集中在 `main.py` 顶部常量区，开箱即用

## 🚀快速开始

### 1. 克隆项目

```bash
# Gitee 镜像（国内访问快）
git clone https://gitee.com/yhl5244/start_points_claimer.git
cd start_points_claimer
```

### 2. 安装依赖

```bash
pip install -r requirements.txt
playwright install chromium
```

### 3. 首次登录

```bash
python main.py login
```

会自动弹出浏览器并点开登录框。本机 QQ 客户端在线时直接点头像快捷登录，无需扫码；没检测到快捷登录才等你用手机 QQ 或微信扫码。脚本检测到登录成功后自动保存状态并关闭窗口。

> 想省掉扫码，先确保电脑上的 QQ 客户端已登录并保持运行。

### 4. 日常运行

```bash
# 场景 1：无头后台运行，领取完自动退出
python main.py run

# 场景 2：弹出浏览器窗口，围观它点
python main.py run --visible

# 场景 3：每天定时自动运行（Windows 计划任务，时间改为你想要的）
schtasks /create /tn "START云游戏领积分" /tr "\"C:\Python312\pythonw.exe\" \"C:\start_points_claimer\main.py\" run" /sc daily /st 09:30 /f
```

> 场景 3 用 `pythonw.exe` 运行全程无弹窗；计划任务里 Python 必须写完整路径，Linux 用户改用 crontab 即可。
>
> **只挂 `run` 这一个任务就够了**，不用再单独挂 `renew`。`run` 内置了三级自救：存档可用就直接领，失效就先灌备份，再不行就自动走 QQ 快捷登录重登，然后继续领取——一次运行把"补登录 + 领积分"都办了。只有 QQ 客户端也不在线时才需要你手动 `login`。

## ⌨️CLI 模式

```text
python main.py <login | run | renew | probe> [选项]
```

### 通用选项

| 参数 | 说明 |
|------|------|
| `--version` | 查看版本号 |

### login

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--wait` | 等待扫码的最长秒数 | `300` |

### run

| 参数 | 说明 |
|------|------|
| `--visible` | 弹出浏览器窗口运行（默认无头） |
| `--keep-open` | 领取完不关浏览器，方便人工检查 |
| `--force` | 忽略当天已运行记录，强制再跑一次 |
| `--check` | 只检测有几项可领取，不点击（忽略当日去重，不写 state.json） |

### renew

| 参数 | 说明 |
|------|------|
| `--visible` | 全程弹出浏览器窗口运行（默认无头） |
| `--no-repair` | 只检查不自动补登录，失效直接返回 2 |

只做登录态检查 + 自动补登录：访问一次首页，让页面自己完成 `capi/login/v1/session` 探活、顺延 `start_uid`、刷新 `session_backup.json`、播报本地凭据到期情况。凭据失效时会自动走「现存档 → 凭据备份 → QQ 快捷登录」三级自救。不点菜单、不领奖、不读积分。

退出码：`0` 成功（含"今天已跑过"跳过）/ `1` 登录超时或运行异常 / `2` 三级自救都失败，需手动 `login`

### probe

无额外参数。走到任务面板后把每个 frame 的可见文字导出到 `logs/dom_dump.txt`，用于页面改版时对照更新 `main.py` 里的 `CLAIM_KEYWORDS`。

## ⚙️参数调整

本项目**零配置、开箱即用**。所有匹配规则集中写在 `main.py` 顶部「内置参数」区，想调整行为直接改常量：

| 常量 | 说明 | 默认值 |
|------|------|--------|
| `HEADLESS` | 无头后台运行 | `True` |
| `CLAIM_KEYWORDS` | 可领取按钮的文案（全字匹配） | `一键领取 / 领取 / 领取奖励` |
| `SKIP_WORDS` | 含这些字样的一律不点 | `已领取 / 去完成 / 前往 / ...` |
| `MAX_ROUNDS` | 领取后最多再扫几轮 | `4` |
| `ENTRY_ASSETS` / `ENTRY_POINTS` | 任务面板入口路径文案 | `我的资产` → `积分` |
| `LOGIN_WAIT_SECONDS` | login 等待扫码秒数 | `300` |
| `LOCAL_NETWORK_FLAGS` | 关掉 Chrome 的本地网络访问检查，QQ 快捷登录才认得出本机 QQ（无头下也能用） | `--disable-features=LocalNetworkAccessChecks,PrivateNetworkAccessChecks` |
| `REPAIR_HEADLESS` | 自动补登录用无头窗口（不闪窗） | `True` |
| `REPAIR_VISIBLE_FALLBACK` | 无头补登录失败后是否回退可见窗口兜底 | `False` |
| `SESSION_WARN_DAYS` | 凭据剩余天数低于此值时提醒 | `7` |
| `SESSION_PROBE_MARK` | 判定登录态用的服务端探活接口（页面自己会调用） | `/capi/login/v1/session` |
| `START_PROFILE_DIR`（环境变量） | 自定义 `profile/` 浏览器存档的存放位置 | 跟随项目目录 |

## ❓️FAQ

**每次运行都要扫码吗？**

不用。`login` 扫一次码后，登录状态保存在 `profile/` 目录；日常只跑 `run` 即可。

**登录态能维持多久？为什么过几天就失效？**

**先说结论：腾讯 START 的登录态无法靠定时访问长期维持，掉线是常态，需要定期重新 `login` 扫码。** 有效期大约 3~7 天，不是 30 天。

具体原因（都可在自己的 `session_backup.json` 里核对）：

| 凭据 | 有效期 | 访问首页会自动续期吗 |
|---|---|---|
| `start_uid` | 30 天 | ✅ 会（唯一会自动顺延的） |
| `pt_guid_sig`、`pt_recent_uins` | 30 天 | ❌ 不会，要真正走一次登录握手才刷新 |
| `ams_qqopenid_*`（业务凭据） | **7 天** | ❌ 不会 |
| `RK`、`qlogin_uid` 等 | 约 1 年 | ❌ 不会 |

也就是说，**只有 `start_uid` 会跟着你每天运行往后滚**，其余凭据从登录那一刻起就定死了。而任务面板读积分要用的 `ams_*` 只有 7 天寿命——它一过期，页面可能仍显示已登录，但积分和任务面板直接读不出数据。

判定"到底还活着没"只信服务端：页面每次加载都会 `POST my.start.qq.com/capi/login/v1/session`，返回 `code=0` 才算真的有效（脚本已内置这条探活，日志里会写 `[登录] 成功` 或 `auth fail` 的具体 code）。看首页有没有"登录"按钮是不可靠的。

最常见的作废原因是**单点互斥**：同一账号同一时刻只允许一个会话，你在网页、手机 App、小程序任何一处重新登录，脚本存的那份就会被挤掉。此外，`profile/` 被其他 Chromium 进程或同步盘动过，也可能让凭据损坏。

那能靠 `renew` 顶住吗？顶不住过期，但能顶住掉线。它只顺延 `start_uid`、拿到服务端探活结果，续不了 `pt_guid_sig` / `ams_*`，也挡不住服务端作废整份凭据；价值在于**失效后能自己爬起来**——先灌回 `session_backup.json`，不行就用 QQ 快捷登录自动重登，全程无需你操作，实际体验是"掉线了但你没感觉"。所以**只挂 `run` 一个每日任务就够**，补登录与领取在同一次运行内完成；`renew` 是独立的轻量检查命令，想单独看登录态时才用（`--no-repair` 可关掉自动补登录）。

**登录态丢了，一定要重新扫码吗？**

不一定。每次成功登录或保活后，脚本会把凭据额外备份到 `session_backup.json`（全量 cookie + localStorage 里的设备指纹）。当 `profile/` 被清理、或 cookie 库意外损坏时，`renew` 与 `run` 会自动尝试用备份免扫码恢复，日志里会写明「已用备份的 N 条凭据免扫码恢复」。

但**备份只能救"本地丢失"，救不了"服务端作废"**：如果凭据已被腾讯那边标记失效（单点互斥、超期、异地登录），灌回去也一样是 `auth fail`。出现 `code=22001` 时，脚本会自己往下走——用 QQ 快捷登录重新登录一次（前提是本机 QQ 客户端在线）。

> 注意：`session_backup.json` 等同于你的登录凭据，已在 `.gitignore` 中排除，**不要提交、不要外传**。

**会不会被腾讯封号？**

脚本不伪造任何请求，只是在真实浏览器里点击真实页面上的按钮，对平台而言和一个正常用户没区别。但请遵守平台规则，仅用于自动领取你本人账号已完成任务的奖励。

**运行后显示"领取 0 次"是坏了吗？**

大概率是当天的任务已经领完了，属正常现象。可以先跑 `python main.py run --check` 只检测不领取，或用 `python main.py probe` 导出页面文字对照确认；若发现按钮文案变了（如"立即领取"），把新文案加进 `main.py` 的 `CLAIM_KEYWORDS` 即可。

**积分余额和过期时间怎么来的？准吗？**

领取完脚本会顺手点开商城页头的「积分明细」，读里面「可用平台积分」和「N 积分将于 X 年 X 月 X 日过期」两行文字，所以报的就是页面上显示的真实数字，与人工点进去看到的一致；页面上没有过期提示时，日志只报总积分并注明"未读到积分过期信息"。
